## Problem Statement

feishu-cc 的核心价值是"手机遥控本机 Claude"和"长任务异步处理"。但反馈回路断了：

1. **完成无通知**：`result` 事件只做 `update_card()`，飞书不产生推送通知。用户必须主动打开飞书才能知道任务完成。
2. **无法软中断**：当前 `stop` 命令杀死整个 session。用户没有 Ctrl+C 等效的"打断当前操作、保留会话"的方式。
3. **状态不明**：切回飞书时，不知道 Claude 是在忙、在等输入、还是已完成。

## What Makes This Cool

完成后，用户体验变成：
- 扔一个任务给 Claude，锁屏走人
- 飞书推送来了 → 打开看结果
- 任务卡住了？发 `/interrupt`，Claude 停下来，直接说"我想改变方向"
- 30分钟后回来，`list` 一眼看出每个 session 在干嘛

这才是真正的"异步 Claude"，不是被动看滚动输出的流式终端。

## Constraints

- 单进程架构，不引入 Redis/外部状态存储
- Python asyncio，不引入额外线程模型
- 飞书卡片更新 ≠ 推送，新消息才触发通知 —— 所有"重要事件"必须发新消息

## Premises (confirmed)

1. 飞书卡片 `update_card()` 不产生手机推送通知 ✓
2. "中断"≠"kill session"：用户想要 SIGINT 语义（停止当前操作，保留会话） ✓
3. 状态不明的核心是：切回飞书时看不出 Claude 正在干嘛 ✓

## Approaches Considered

### Approach A: 三项独立小改
Effort: S | Risk: Low
- result 时 `_notify()` 额外一条消息
- `/interrupt` → SIGINT
- `list` 显示 is_busy
Pros: 快，独立，< 60 行
Cons: 无进度心跳，30分钟黑盒；无统一状态模型

### Approach B: 会话状态机（选定）
Effort: M | Risk: Medium
- 引入 `SessionStatus` enum: idle / running / waiting_permission / done（无 waiting_input）
- 状态转换驱动通知，不再是"event type 驱动消息"
- heartbeat task：可配置间隔，超 N 秒自动发进度消息
- `/interrupt`：SIGINT 语义

## Recommended Approach: B — 会话状态机

### 架构变更

**1. 新增 SessionStatus**

```python
# server/session_status.py（新文件）
from enum import Enum

class SessionStatus(Enum):
    IDLE = "idle"           # 等待用户输入（含已完成状态）
    RUNNING = "running"     # Claude 正在执行
    WAITING_PERM = "waiting_permission"  # 等待权限决策
    # 注：无 DONE 状态；result 后转 IDLE 即可，list 无需区分"从未运行"和"运行完成"
```

**2. Session 增加状态字段**

```python
@dataclass
class Session:
    ...
    status: SessionStatus = SessionStatus.IDLE
    status_since: float = field(default_factory=time.monotonic)
    last_heartbeat: float = field(default_factory=time.monotonic)
```

**3. on_executor_event 状态转换**

| 事件 | 当前状态 → 新状态 | 是否发新消息 |
|------|-----------------|------------|
| system/init（进程 spawn 后第一个事件） | → RUNNING | 否 |
| assistant（有内容） | → RUNNING（已是则不变） | 否（用 card update） |
| result（success） | → IDLE | **是** ✅（触发推送） |
| result（error） | → IDLE | **是** ❌（触发推送） |
| permission request | → WAITING_PERM | 否（已有 card） |
| permission resolved | → RUNNING | 否 |
| on_executor_exit | → IDLE | **是** ⚠️（触发推送） |

注：`start_session` 成功后 session 状态初始为 IDLE，等到 `system/init` 事件再转 RUNNING。
这保证 `list` 在进程真正启动前不会显示 running。

**4. 完成通知（核心改动）**

`_notify` 内部优先调用 `_feishu_card_sender`（发卡片）。由于卡片更新不触发推送，完成通知必须走纯文本消息路径。

最干净的实现：给 `_notify` 加 `force_text=True` 参数，使其跳过 card sender 直接调 `_feishu_sender`，避免业务层直接操作底层 sender。

`render.extract_result_summary(event)` 当前返回格式为：`"✅ 完成 · 5.2s · $0.0021"`（已含耗时和费用），直接作为通知消息内容即可，无需额外拼装。

现有代码末尾有 `if not (state and state.message_id): await self._notify(...)` —— 这个条件分支是"没有卡片时的降级"，需要改为**无条件**发推送通知，同时保留卡片 update（两者并存：卡片是详情，通知消息是推送触发器）。

```python
# manager.py：_notify 新增 force_text 参数
async def _notify(self, chat_id: str, text: str, reply_to=None, force_text: bool = False) -> None:
    if not force_text and self._feishu_card_sender:
        # 发极简卡片（现有行为不变）
        await self._feishu_card_sender(chat_id, text)
    else:
        # 纯文本消息，触发手机推送
        await self._feishu_sender(chat_id, text, reply_to)

# manager.py on_executor_event, etype == "result" 分支
elif etype == "result":
    summary = render.extract_result_summary(event)  # 已含耗时/费用
    # 1. 保留现有逻辑：更新/发送卡片（不变）
    if state and state.message_id:
        card = self._build_turn_card(..., done=True, summary=summary, ...)
        await self._update_turn_card(state.message_id, card)
    # 2. 新增：无条件发纯文本通知 → 触发手机推送
    sess.status = SessionStatus.IDLE
    self._cancel_heartbeat(session_id)
    await self._notify(sess.owner_chat_id, summary, force_text=True)
```

**进程异常退出通知**：`on_executor_exit` 也需要补充通知，避免 crash 后状态挂死。

注意现有签名为三参数：`on_executor_exit(self, session_id: str, exit_code: Optional[int], reason: str)`

```python
async def on_executor_exit(self, session_id: str, exit_code: Optional[int], reason: str) -> None:
    sess = self._sessions.get(session_id)  # 先 get 取引用
    if sess:
        self._cancel_heartbeat(session_id)
        msg = f"⚠️ 会话 `{session_id}` 已退出（{reason}，exit_code={exit_code}）"
        await self._notify(sess.owner_chat_id, msg, force_text=True)
    # 现有清理逻辑：pop session + 清 bindings（必须保留，顺序不变）
    self._sessions.pop(session_id, None)
    for b in self._bindings.values():
        if b.session_id == session_id:
            b.session_id = None
```

**5. Heartbeat（可选，环境变量配置）**

heartbeat task 的生命周期：
- **启动点**：`on_executor_event` 处理 `assistant` 事件时，若 `sess.status` 从非 RUNNING 转为 RUNNING，调 `asyncio.create_task(_heartbeat_loop(session_id))` 并把 task 引用存入 `self._heartbeat_tasks[session_id]`
- **取消点**：状态转换离开 RUNNING 时（result 事件 / on_executor_exit），取消并删除对应 task

```python
# config.py 新增
heartbeat_interval: int = int(os.getenv("FEISHU_CC_HEARTBEAT_INTERVAL", "0"))  # 0=关闭

# manager.py
# 新增字段
self._heartbeat_tasks: Dict[str, asyncio.Task] = {}

def _start_heartbeat(self, session_id: str) -> None:
    if session_id in self._heartbeat_tasks:
        return  # 已在跑，不重复启动
    task = asyncio.create_task(self._heartbeat_loop(session_id))
    self._heartbeat_tasks[session_id] = task

def _cancel_heartbeat(self, session_id: str) -> None:
    task = self._heartbeat_tasks.pop(session_id, None)
    if task and not task.done():
        task.cancel()

async def _heartbeat_loop(self, session_id: str) -> None:
    interval = self._config.heartbeat_interval
    if not interval:
        return
    try:
        while True:
            await asyncio.sleep(interval)
            sess = self._sessions.get(session_id)
            if not sess or sess.status != SessionStatus.RUNNING:
                break
            elapsed = int(time.monotonic() - sess.status_since)
            await self._feishu_sender(sess.owner_chat_id, f"⏱ 执行中 · 已 {elapsed}s…", None)
    except asyncio.CancelledError:
        pass  # 正常取消
```

**6. 软中断 `/interrupt`**

SIGINT 后有两种情况：
- **情况 A（正常）**：Claude 收到 SIGINT，输出一次 result 事件后退出 → `on_executor_event` 正常处理，状态转 IDLE，通知推送
- **情况 B（直接退出）**：Claude 直接退出不输出 result → `on_executor_exit` 触发，依赖其中的通知逻辑（见第 4 条）

无论哪种情况，用户都会收到通知。但为避免 Claude 既不输出 result 也不触发 exit（极端情况），在命令侧加 5 秒超时兜底：

```python
# runner.py
async def interrupt(self) -> None:
    """发 SIGINT，等效 Ctrl+C，不杀进程。"""
    if self._proc and self._proc.returncode is None:
        self._proc.send_signal(signal.SIGINT)

# executor.py
async def interrupt_session(self, session_id: str) -> None:
    runner = self._runners.get(session_id)
    if runner:
        await runner.interrupt()

# commands.py
async def _cmd_interrupt(m, open_id, chat_id, _):
    sess = m._current_session(open_id)
    if not sess:
        await m._notify(chat_id, "❌ 没有活动会话")
        return
    await m._executor.interrupt_session(sess.session_id)
    await m._notify(chat_id, "⏹ 已发送中断信号，Claude 正在停止当前操作…")
    # 5s 超时兜底：fire-and-forget task，不阻塞 handler 协程
    # 记录 interrupt 时刻的 status_since，避免新 prompt 启动后误判
    interrupt_status_since = sess.status_since
    async def _interrupt_timeout_guard():
        await asyncio.sleep(5)
        # 同时校验：仍为 RUNNING 且 status_since 未变（排除新 prompt 进入 RUNNING）
        if sess.status == SessionStatus.RUNNING and sess.status_since <= interrupt_status_since + 0.1:
            sess.status = SessionStatus.IDLE
            await m._notify(chat_id, "⏹ 已中断（超时兜底）", force_text=True)
    asyncio.create_task(_interrupt_timeout_guard())

_ROUTES["interrupt"] = _cmd_interrupt
```

- heartbeat 默认关闭，避免噪音

## Open Questions

1. `result` 后的 `_notify()` 跟原有的 card update 是两条消息，会不会重复？
   → 建议：card 保留完整对话记录，新消息只发一行摘要（✅ 完成 · 5.2s · $0.0021）

2. SIGINT 后 Claude 的行为是否符合预期？
   → 需要**先手工验证**（见 Next Steps 步骤 0）再实现 /interrupt。两种情况处理方案已写入第 6 条实现中。

3. heartbeat 消息太多会刷屏，应该设多少为默认值合适？
   → 建议：默认 0（关闭），文档建议 120s-300s 供用户自行配置

4. WAITING_PERM 期间长时间无响应是否需要额外通知？
   → 当前设计：不单独通知，权限请求已内嵌在卡片里，用户负责响应。
   若未来发现权限等待超时是痛点，可在 heartbeat 扩展阶段一起处理。

## Success Criteria

- [ ] 任务完成后，飞书推送新消息（不只是 card update）
- [ ] 发送 `/interrupt` 后，Claude 在 3s 内停止当前操作，session 保持活跃
- [ ] `list` 命令显示每个 session 的当前状态（idle/running/waiting_permission）
- [ ] heartbeat 可通过环境变量配置，默认关闭
- [ ] 进程异常退出（crash/kill）时，飞书收到异常退出通知
- [ ] 所有改动不影响现有的 card 展示、权限弹窗、文件展开功能
